# Передача проекта Swanky Pro × Moodnail

Дата подготовки: **27 октября 2026 года**. Язык проекта и основной рынок — Россия.

Это инструкция для нового аккаунта ChatGPT / Codex. Она сопровождает **редактируемый исходный проект**, из которого был собран `Swanky-Pro-Concept.html`. Готовый HTML — только дополнительный эталон просмотра; продолжать разработку следует по React/TypeScript-исходникам.

## 0. Самое важное для следующего ИИ

1. Не пересоздавать сайт по описанию или по HTML. Использовать сохранённый код.
2. **Moodnail получил одобрение пользователя: его визуальную идентичность и существующий интерфейс не менять без нового задания.**

4. Не публиковать изменения, не обновлять действующий сайт и не подключать платёжные действия без отдельного разрешения пользователя.
5. Работать по обычным сообщениям пользователя: самостоятельно читать исходники, вносить правки, запускать проверки и возвращать результат. Не требовать, чтобы пользователь писал код.

8. Исторические документы в `project/docs/` описывают разные итерации и местами устарели. Приоритет: последнее задание пользователя → этот handoff → текущий код → старые документы.

## 2. Что реализовано и что является демонстрацией

### Реализовано в интерфейсе

- Два отдельных брендовых пространства с общим переключателем.
- Самостоятельные главные, каталоги и карточки товаров.
- Moodnail: визуальные коллекции, категории, подборки настроений, переключаемые кампании, интерактивные mood-блоки и записки.
- Swanky: приоритет ухода, два входа «Уход» / «Стемпинг», новинки, коллекции, редакционные истории, образ с пластиной 202, сборка ритуала.
- Swanky hero: три предложения, кнопки разделов, стрелки, клавиши ← / →, свайп; без автоматического перелистывания.
- Карточки Swanky: две фотографии с перекрёстным затуханием, сенсорный переключатель ракурса, избранное, заполненная кнопка покупки и состояние «Добавлено».
- Поиск, результаты и пустые результаты; фильтры и сортировка в каталогах.
- Галереи с увеличением; количество, описание, применение, состав для ухода, связанные продукты.
- Общая корзина и боковая мини-корзина, изменение количества, удаление и пересчёт.
- Демо-оформление, сохранение демо-заказа в общем профиле.
- Формы входа/регистрации Swanky, редактирование профиля, история заказов.
- Адаптивные CSS, мобильное меню, нижняя навигация, закреплённая кнопка покупки; фокусы, короткие переходы и reduced motion.

«Реализовано» означает наличие кода и состояний. Это не утверждение, что все браузерные взаимодействия уже были проверены вручную.

### Демонстрации и незавершённые интеграции

- Нет серверного каталога, синхронизации цен/остатков, CMS, настоящего оформления и отправки заказов.
- Нет настоящей авторизации, восстановления пароля и межустройственной синхронизации. Пароль из формы Swanky не сохраняется.
- Нет эквайринга и списания денег. Карта/СБП в Swanky checkout — макеты вариантов, не подключённые способы оплаты.
- Нет работающей карты ПВЗ, доставки, подтверждённых тарифов и сроков. У Swanky предусмотрена заглушка интеграции.
- В Moodnail / старом общем commerce сохранены условные демонстрационные тарифы и код `MOOD10`. Это не согласованная коммерческая акция.
- В актуальном Swanky не применяется вымышленный промокод: показано ожидание подтверждения правил. Общие товары одни, но логика скидок/доставки двух оболочек ещё требует унификации.
- Нет реальных отзывов, подключённой UGC-ленты, статистики продаж и настоящих рейтингов. «Выбор редакции» — редакционная подборка, не рейтинг продаж.
- Концептуальные изображения моделей не являются фотографиями реальных покупателей или подтверждением результата от конкретного SKU.
- «Ритуалы» — сочетания отдельных товаров без нового SKU и обещания скидки.
- Блоки `db/`, `examples/d1/`, ChatGPT sign-in helpers сохранены как возможности шаблона. Они не означают подключение магазина к реальной базе или авторизации.

## 3. Дизайн и требования к брендам

### Moodnail — согласованная идентичность

Пользователь прямо подтвердил, что в Moodnail найдено нужное визуальное направление. Последующие задачи касаются Swanky.

- Уличный fashion-журнал и «свой круг»: дружба, живые фотографии, индивидуальность, городской контекст.
- Тёплая бумага `#F2EFE4`, тёмный сливовый текст `#34263C`, лиловая планка `#CBB9DD`; локальные жёлтые, вишнёвые и оливковые кампанийные оттенки.
- Плотная гротескная типографика, редакционные смещения, рамки и небольшие печатные детали.
- Основная навигация: «Каталог», «Твой mood», «Акции», «Новинки», «О бренде».
- Визуальные категории/коллекции ведут к товарам. В карточках Moodnail убраны блоки старых образов.
- Не возвращать видео-led главную: прежний видео-компонент сохранён в исходниках, но не используется актуальной главной.
- Продуктовые упаковки и изображения не перерисовывать.

Точные актуальные значения и композицию смотреть в `app/moodnail-club.css` и текущем компоненте, а не восстанавливать по этому тексту.

### Swanky Pro — «Отпечаток и ощущение»

Внутренняя идея — **MARK & FEEL**. Публичная кампания — «Ощущать. По-своему.». Это один lifestyle/beauty-бренд с двумя связанными направлениями:

- Уход: текстуры, кожа, аромат, ежедневный ритуал. Он получает приоритет в первом впечатлении.
- Стемпинг: графика, точность переноса, рисунок, самовыражение. Он остаётся источником узнаваемого визуального языка.

Пять фирменных приёмов:

1. Метка переноса из трёх неполных смещённых контуров.
2. Смещённая тонкая рамка редакционного кадра.
3. Крупная кириллическая типографика и управляемый сдвиг строки.
4. Тактильная фотография: кожа, крем, масло, металл, гравировка.
5. Контролируемый цветовой импульс на спокойной основе.

Палитра последней итерации:

| Цвет | Роль |
| --- | --- |
| `#111216` | Графит, текст и тёмные акцентные истории |
| `#F5F3F0` | Основной светлый фон |
| `#C5CBD0` | Холодное серебро, рамки и нейтральные материалы |
| `#4655FF` | Кобальт: фирменная верхняя планка, покупки, выбранные элементы |
| `#FF3D87` | Электрический розовый: новинки, избранное, небольшие акценты |

Шрифты Swanky: **Unbounded 500** для заголовков, **Manrope 400/600/700** для интерфейса. Кириллица обязательна; локальные файлы и OFL-лицензии включены.

Правила: примерно 80% спокойной торговли и 20% брендовой выразительности; один основной визуальный акцент на экран; минимум английских слов, кроме собственных названий продуктов и бренда. Не превращать сайт в полностью розовый мир, чёрный cyberpunk, перегруженный Y2K, стерильный бежевый skincare или декоративный арт-проект, мешающий покупке.

Логотип и форма существующих упаковок не меняются без отдельного задания. Реальные упаковки находятся в `public/images/swanky/real/`; сгенерированный care-кадр явно обозначен как концепт.

### Общая платформа

Верхняя планка двух брендов имеет одинаковую композицию и поведение. По последнему заданию разрешено различать её цвет: Moodnail — лиловый, Swanky — кобальтовый. У брендов не должно быть двух раздельных корзин или профилей.

## 4. Решения из предыдущих обсуждений

### Подтверждено пользователем

- Идентичность Moodnail устраивает; при поиске Swanky её не трогать.
- Swanky должен быть технологичным, современным, стильным, молодым и дерзким.
- Косметика и стемпинг — один бренд; уход заметнее на первом экране.
- Нужен полный магазин и интерактивная система, а не один красивый hero.
- Для России — русские интерфейсные тексты, понятные цены и привычная покупка.
- Реальные упаковки, достоверные факты; не выдумывать цены, преимущества, отзывы, условия доставки.
- Текущую базовую концепцию Swanky пользователь оценил «не плохо», затем попросил больше цвета и интерактивных мелочей.
- Последнее задание: исправить перекрытие второго фото первым; сделать нормальную заметную кнопку покупки; добавить фирменные цвета; разрешить перекраску верхней планки; сделать смену главных баннеров.
- Требование текущей передачи: сохранить редактируемые исходники, не менять дизайн и функциональность при упаковке.
- Публикация действующего сайта — только по отдельному разрешению.

### Реализовано по последнему заданию, но не выдаётся за окончательное утверждение

- Основной акцент сделан кобальтовым, розовый оставлен локальным.
- Исправлены слои/непрозрачность фото; есть отдельное сенсорное управление.
- Кнопки покупки заполненные, с подтверждением добавления.
- Введены три переключаемые кампании Swanky.
- Добавлены короткие реакции навигации, избранного, фильтров, ритуала и раскрываемых описаний.

После этой итерации отдельного сообщения пользователя «финально утверждено» не было. Считать её текущей рабочей версией, не навязывать новую концепцию и не объявлять завершённый бренд-тест.

## 5. Незавершённые задачи и следующий этап

### Сначала — восстановить рабочий проект

1. Распаковать, прочитать этот документ и проверить манифест.
2. Установить зависимости из lock-файла, не меняя версии.
3. Восстановить Git-историю из bundle, чтобы работала проверка сохранности Moodnail.
4. Выполнить кодовые проверки и запустить предпросмотр.
5. Показать пользователю текущую версию, сохранив её вид, прежде чем предлагать дополнительные изменения.

### Проверка интерфейса

- Desktop 1440 px, tablet около 768 px, mobile 390 px и промежуточные ширины.

## 6. Ошибки, ограничения и обязательные проверки

### Проверено ранее и при передаче

В последней дизайн-итерации прошли TypeScript и production build. SSR-проверка охватывает **175 адресов**, связанные страницы, существование изображений и отношения товаров; в каталоге **39 SKU: 18 Moodnail и 21 Swanky**. Проверка маршрутизации включает 19 случаев, общий профиль, смешанный демо-заказ и повреждённые локальные данные. Рендер 13 страниц Moodnail сравнивается с предыдущей версией.

Фактический повторный результат проверки архивной копии фиксируется в `VERIFICATION.md` внутри ZIP. Это отдельный отчёт; не подменять его общими утверждениями этого раздела.

### Известные ограничения

1. **Браузерная QA не завершена.** В прежней среде supervisor preview сообщал о другом уже работающем Vinext-сервере и не достигал healthy-состояния. Это ограничение инфраструктуры, не доказанная ошибка React. Не обходить его изменением дизайна, сетевых разрешений или публикацией без разрешения.
2. SSR и сборка не проверяют реальное наведение, тач, все размеры экрана и сценарий кликов целиком.
3. Восстановление чистой установки зависимостей через интернет в новом аккаунте/ОС может зависеть от registry и доступа к нативным пакетам. Lock-файл и политика установки сохранены; не удалять их ради обхода ошибки.
4. Исторический `README.md` наследует инструкции шаблона, в том числе упоминания npm ci. **Актуальный проект — pnpm**, а `install:ci` в package.json вызывает Linux/Bash-скрипт. На Windows/macOS для самостоятельного запуска использовать прямую установку pnpm по разделу 7.
5. `scripts/check-moodnail-preservation.mjs` использует `git show` коммита `228ed5bfd75d29b195e6082244b17103e9801f78`. Без восстановления истории этот тест не работает. Bundle включён именно для сохранения этой возможности.
6. В каталоге неизвестные цены внутренне представлены `0`, но UI Swanky показывает «Цена уточняется» и не разрешает покупку. Не трактовать `0` как бесплатный товар и не менять на выдуманную цену.
7. Цены — срезы **19.10.2026** и **25.10.2026**, даты хранятся в метаданных. При упаковке 27.10.2026 цены заново не исследовались. Состав крема с пачули требует подтверждения.
8. Прямой доступ к Instagram был ограничен; актуальную ленту Telegram в последнем исследовании прочитать не удалось. Старые docs могут упоминать публичное зеркало; это не полный аудит свежих соцсетей.
9. Swanky-избранное выводит товары обоих брендов. Старые сохранённые `look:`/`mood:`-ключи могут оставаться в storage, но не отображаются в этой новой товарной сетке. Нужна согласованная миграция представления, а не удаление данных.
10. Старые URL образов Swanky, кроме `plate-202` и `ritual`, показывают «Образ обновляется». Старые смешанные образы сохранены в данных/истории, но не выдаются за реальные подтверждённые рецепты нового раздела.
11. Не подтверждена безусловная сохранность несохранённых полей и шага при переключении окружения общих checkout/профиля. Общность сохранённых данных проверена; жизненный цикл форм двух разных компонентов нужно проверить отдельно.
12. У общего старого commerce и нового Swanky есть различия в демонстрационной скидке/доставке. Перед запуском нужна единая бизнес-логика, не визуальное смешение брендов.
13. `scripts/export-swanky-review.mjs` содержит старый абсолютный путь по умолчанию. Всегда передавать свой выходной путь аргументом, не менять код ради переноса.
14. Новый аккаунт не получает автоматически прежний Sites-домен, права проекта, историю диалога, учётные данные или браузерный localStorage. Исходники и Git-история передаются архивом; доступы оформляются отдельно.

### Что отсутствует и что не подменялось

- **Отсутствующих текущих отслеживаемых исходников не обнаружено.** Приблизительные замены не создавались.
- В архиве нет исходного редактируемого Figma-файла: он не использовался для этой реализации и не найден среди исходников.
- Оригинальные PSD/RAW/проекты видеоредактора, не сохранённые в рабочей среде, не восстановлены. Переданы реальные доступные PNG/JPEG/WebP/MP4, а не выдуманные «исходники».
- Точные промпты ряда старых кампаний сохранены в исторических docs. Для care-кадра Swanky гарантированно сохранены финальный WebP и исходный PNG; полный исходный tool-log/промпт в отдельном файле не найден, его текст не реконструировался.
- Нет базы реальных заказов, клиентов и складского учёта. Их не существовало в этом прототипе.
- Не включены установленные `node_modules`, кэши, временные runtime-профили, build outputs, авторизационные настройки Git и служебные логи. Это не исходники; их назначение описано в `ARCHIVE_CONTENTS.md`.
- Полный старый чат не экспортирован. Этот handoff и сохранённые docs передают доступные договорённости, а не обещают восстановление истории аккаунта.

## 7. Запуск и продолжение через Codex

### Для пользователя: что загрузить в новый аккаунт

1. Создать новый диалог/проект с доступной средой разработки Codex.
2. Загрузить **полный ZIP**, а также отдельно этот `PROJECT_HANDOFF.md`, если интерфейс позволяет.
3. Отправить ИИ следующий текст. Писать код самостоятельно не требуется.

> Продолжаем существующий проект интернет-магазина Swanky Pro × Moodnail. В ZIP находятся редактируемые исходники, а не только HTML. Распакуй архив, прочитай PROJECT_HANDOFF.md, ARCHIVE_CONTENTS.md и VERIFICATION.md. Не пересоздавай проект и не обновляй зависимости. Проверь SOURCE_MANIFEST.json, восстанови Git-историю из history/project-history.bundle, установи зависимости по pnpm-lock.yaml и запусти текущую версию. Сохрани существующие дизайн и функциональность; Moodnail уже согласован. Не публикуй сайт и не используй прежний project_id для деплоя без отдельного разрешения. Выполняй технические действия самостоятельно, а со мной согласовывай изменения обычным диалогом. Сначала покажи текущую версию и сообщи, какие проверки прошли. Если файлов или возможностей среды не хватает, перечисли конкретный недостаток, не создавай приблизительную замену.

Само вложение ZIP не создаёт автоматически рабочую серверную среду. Если в новом аккаунте нет инструментов исполнения или загрузка ZIP недоступна, понадобится доступ к Codex/среде разработки; это ограничение возможностей аккаунта, не потеря проекта.

### Для Codex: чистое восстановление Git

В архиве `project/` уже содержит файлы. Для возврата Git-истории из корня `Swanky-Moodnail-Source/`:

```sh
git clone history/project-history.bundle restored-project
```

`restored-project/` будет клоном того же исходного коммита с историей. Это удобный способ продолжать разработку; материалы/документация остаются рядом. Не удалять имеющийся `project/` до сверки. Можно работать прямо в `project/`, импортировав историю без перезаписи файлов:

```sh
cd project
git init
git fetch ../history/project-history.bundle refs/heads/main:refs/remotes/archive/main
git reset --mixed refs/remotes/archive/main
```

Здесь намеренно нет `reset --hard`. Git remote на старый аккаунт не передан. Импорт bundle не требует доступа к прежнему аккаунту. После импорта создать отдельную рабочую ветку, например `git switch -c continue-design`.

### Установка и dev-сервер

Работать в корне `project/` или `restored-project/`, где лежит package.json. Нужны Node.js, pnpm и доступ к npm registry. Для воспроизводимости предпочтителен Node 24.22.1 и **pnpm 11.25.0**.

Если pnpm этой версии ещё не доступен, установить его в среду или использовать настроенный Corepack; это выполняет Codex. Обычный вариант:

```sh
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile --prod=false
pnpm dev
```

В самостоятельной среде без `.sites-runtime/execution-profile.json` код выбирает профиль `portable`. Dev-порт по умолчанию **5173**. Открывать URL, который действительно напечатал сервер; обычно `http://localhost:5173/moodnail` и `http://localhost:5173/swanky-pro`.

Не запускать `npm install`, не генерировать package-lock.json и не удалять pnpm-lock.yaml. Не копировать чужой `node_modules`: нативные пакеты отличаются для Linux, Windows и macOS. Если пользователь работает с ИИ в облаке, именно ИИ запускает команды в своей среде.

Если разработка идёт в управляемой среде ChatGPT Sites, использовать её актуальный навык Sites и штатные configure/install/preview-процедуры. Внутренние CLI и пути текущего аккаунта не являются частью исходного проекта; старый runtime-профиль специально не перенесён. Не подменять штатный браузерный preview самодельным сервером для обхода ограничений.

### Проверки

```sh
pnpm exec tsc --noEmit --incremental false
node scripts/check-prototype.mjs
node scripts/check-brand-spaces.mjs
node scripts/check-moodnail-preservation.mjs

```

Последний скрипт сохранности Moodnail требует импортированной истории Git. Проверки запускать из каталога проекта, не из родительской папки. Lint не был текущим обязательным gate; не менять весь старый код форматированием ради упаковки.

После сборки `pnpm start` запускает локальную Worker-версию через Wrangler. Это локальный просмотр, не публикация; использовать напечатанный адрес.

### Экспорт HTML после новых правок

Только когда нужен отдельный автономный просмотр, из корня проекта:

```sh
node scripts/export-swanky-review.mjs ./Swanky-Pro-Concept.html
```

Явный выходной путь обязателен при переносе. Экспорт использует исходники и локальные ресурсы, временно создаёт `.offline-review/`, затем удаляет её. Готовый HTML работает с hash-маршрутами; серверный проект использует обычные URL. Исходный проект не заменять этим HTML.

### Как вносить следующие изменения

1. Читать конкретный запрос и этот handoff; не начинать повторный поиск новой концепции без задания.
2. Для Swanky менять `swanky-system.tsx`, его CSS и отдельные данные. Для баннеров сначала смотреть `data/swanky-campaigns.ts`.
3. Общие функции корзины/профиля и маршрутизацию менять только с проверкой обоих брендов.
4. Не редактировать `data/products.json` ради вымышленных цен или переименования упаковки. Неизвестные параметры держать явно неподтверждёнными.
5. Проверить текущий запрос, доступность и адаптацию; затем сохранить понятный коммит и обновлённый результат просмотра.
6. Публикация — отдельное действие после разрешения пользователя.
